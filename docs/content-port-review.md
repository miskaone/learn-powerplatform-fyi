## Misconception taxonomy (17 named)

Consolidated across all five lessons' distractors; a shared id means the same
mental-model gap fires across lessons, which is what makes repeated-misconception
routing meaningful. Every distractor option in the bank carries exactly one id.

| misconception id | name | contrast | source lessons / distractors |
|---|---|---|---|
| `oauth-chain-unordered` | OAuth chain as a checklist | Consent approves an already-requested permission, and each stage of Register, Permission, Consent, Connect, Call depends on the one before it. The chain is a dependency order, not an unordered setup checklist. | ML-13 "Grant consent before requesting permission"; ML-13 wrong-order options (q1), skipped-stage options (q3, q7) |
| `permission-mode-ignores-actor` | Permission mode chosen by data sensitivity | A signed-in Canvas user normally implies delegated access; application permissions fit unattended daemon and background processes. The caller identity, not how privileged the data feels, selects the permission mode. | ML-13 "Application permissions for the interactive user" (q3, q7) |
| `auth-controls-conflated` | Role, permission, and consent collapsed | A directory role is assigned to a user; a Graph permission is requested by an app; consent approves the app request. They are separate controls and must not be merged into one authorization concept. | ML-13 "Directory role equals Graph consent" (q2, q4, q5, q6); reused for ML-12 q4 (compute choice confused with authorization) |
| `client-side-is-server-side` | Client code as a server boundary | Hiding a screen or running browser JavaScript is user experience, not enforcement or compute. Web resources have no server-side execution capability, and a protected operation must validate authorization independently. | **Shared:** ML-13 "Hiding the screen is authorization" + ML-11 "Web Resource + Dataverse Web API"; fires in ML-13 q6/q7, ML-11 q1–q4/q6/q7, ML-12 q3 |
| `component-role-collapse` | One component absorbs every job | A webhook is event delivery; the Azure Function is custom compute; the Web API loads data; a custom connector describes how consumers call an API. No component absorbs its neighbor's job. | **Shared:** ML-11 "Webhook performs the transformation" + "Custom Connector + Microsoft Graph" + ML-12 "Dataverse Web API stores SharePoint files"; also ML-13 q4 (connector as consent/authorization) |
| `trigger-ignores-origin` | Trigger chosen without naming the event origin | Dataverse webhooks originate from Dataverse server events and send them outward. A scheduled pull from legacy systems needs a timer, pipeline, dataflow, or source-side trigger. | ML-11 "Use a Dataverse webhook to schedule legacy extraction" (q2, q7) |
| `flow-scales-to-bulk` | Cloud flow as a bulk migration engine | A high-volume initial migration needs controlled batching, checkpoints, retries, reconciliation, and restartability that a purpose-built batch application handles more directly. Cloud flows fit modest ongoing workloads. | **Shared:** ML-11 "Power Automate + Microsoft Graph" + ML-12 "Power Automate" (q2, q4) |
| `policy-precedence-instinct` | One policy wins by precedence | Power Platform evaluates all applicable data policies together. Neither nearest scope nor most-recent edit creates an override: Blocked takes precedence and groupings intersect. | ML-09 "Environment-level always overrides tenant-level" + "The most recent policy wins" (q1–q7) |
| `labels-are-ranks` | Business as a permission rank | Business and Non-Business are separation groups, not allow-and-deny levels or quality ratings. Compatibility depends on staying grouped together under every applicable policy; Non-Business is not Blocked. | ML-09 "Business is more permissive, so it overrides Non-Business" (q1–q4, q7) |
| `single-policy-view` | One policy view looks conclusive | Two unblocked connectors must share the same classification fingerprint across all applicable policies. Sharing a group in one policy, or a majority, is insufficient. | ML-09 "If two connectors share one policy group, they can be used together" (q3, q4, q7) |
| `design-time-only-enforcement` | DLP checks only at save time | Policies are enforced at runtime too: existing resources can become noncompliant after a change, a violating flow saves but is Suspended, and suspension polls so it may not be instantaneous. | ML-09 "A policy change affects only new or edited resources" (q5, q6) |
| `capability-equals-fit` | It can store the bytes, so it fits | Raw capability is not fit. Blob Storage needs a custom record-to-blob experience; Notes consume Dataverse capacity; SharePoint provides the standard document experience in model-driven record context. | ML-12 "Azure Blob Storage" + "Dataverse Notes" (q1, q2, q5, q6) |
| `identity-by-name` | Record matching on mutable names | An alternate key on a stable source identifier resolves the right record when the Dataverse GUID is unknown. Display names are mutable and fragile. | ML-12 (from the `customer-record` concept + q3/q6 distractor options; not a lesson-level distractor) |
| `return-shape-confusion` | Function chosen by keyword, not return type | Filter returns a table; LookUp returns one record; DateAdd returns a date/time; DateDiff returns a number; Set returns no value. The return type decides where each function can be used. | ML-14 "LookUp(Orders, 'Shipping Date' = DateDuration)" + "Set(DateDuration, DateDiff(...))" (consolidated; q1–q7) |
| `behavior-in-data-property` | Set inside a data formula | Set is behavior-only with no return value and does not auto-recalculate. Gallery.Items is a data formula that must evaluate to a table. | ML-14 "Set(...) as a separate statement in Gallery.Items" (q4, q5, q6) |
| `delegation-assumed` | Delegation as a generic function property | Delegation is connector-, operator-, and column-type-specific. A warning means the app may evaluate over a limited local subset and silently omit rows. | ML-14 "Assume Filter is always delegable" (q2, q6) |
| `one-sided-window` | An upper bound treated as a window | An upper bound alone admits every older row. A true next-seven-days window needs both boundaries; for date-time data an exclusive next-day upper bound covers all of day seven. | ML-14 (from `productionNuance` + the `date-window` concept; fires in q7) |

## Converter decisions the owner should ratify

1. **`dimension` metadata (schema proposal).** The frozen schema has no
   per-question dimension field. Each manifest question carries an extra
   `dimension` JSON property (`recall|connections|application|transfer`) that the
   schema types do not declare — ignored by the validator, never crosses the tool
   boundary (redaction is field-by-field), harmless under the existing
   `as unknown as ContentManifest` cast. **Proposal:** add
   `dimension?: RubricDimension` to `Question` in `schema.ts`. The schema was NOT
   changed in this port.
2. **Deterministic option rotation.** Every source spec keys the answer at
   index 0. Options are rotated per question (`display[i] = source[(i + k) % 4]`,
   `k = question ordinal % 4`) so the correct answer is not always option A.
   Resulting spread across the bank: position a×10, b×5, c×9, d×10.
   Wording, answer mapping, and misconception mapping are preserved exactly.
3. **Section anchors.** Four per lesson: `{slug}-rule` (heroEpigraph +
   governingRule), `{slug}-exam-clue` (examClue + mnemonic), `{slug}-scenario`
   (prompt + expected answer), `{slug}-production` (productionNuance bullets).
   Remediation anchors by dimension: recall/connections → `-rule`,
   application → `-scenario`, transfer → `-production`.
4. **Backticks stripped from plain-text section bodies** (UI renders them
   literally); the markdown lesson files keep source text verbatim.
5. **`apps/web/lib/content.ts` now imports generated
   `content/pl-400/lesson-sections.json`** instead of a hand-maintained array, so
   lessons/manifest/sections cannot drift. `DEMO_MASTERY_QUOTE` is now
   "A policy is not a vote; it is a boundary." (ML-09 epigraph, verbatim
   lesson-body text — guarded by `content.test.ts`).
6. **SAMPLE remnants intentionally kept:**
   `content/pl-400/lessons/objective-1-placeholder.md`,
   `objective-2-placeholder.md`, and
   `content/pl-400/flip-conditions/sample-flip-scenario.json`. The sample
   Flip-Condition scenario (ISC-43 is separate, owner-authored work) cites the
   placeholder lessons' anchors; deleting them would break `validate:content`.
   Nothing in the manifest or UI references them. Replace all three together
   when the real flip scenarios are authored.
7. **Source specs are not vendored** into this public repo; the converter takes
   the spec directory as an argument. Only the ported output is committed.
   Drills, reflection prompts, visual step traces, and references from the specs
   were not ported (no schema home); they remain available in the source specs.

## Addendum — micro-lesson restore cross-review fixes (2026-08-27)

1. **ML-08 / ML-10 omission is deliberate, not silent** (cross-review finding 1).
   Two more designed lessons exist in the source family:
   `PL400-ML-10-power-pages-identity-actor` (full spec JSON present in the spec
   directory) and `PL400-ML-08-canvas-app-cross-host-selection` (spec only as an
   embedded `pl400-spec` payload inside its rendered HTML). They are NOT ported
   because the owner's design contract for the micro-lesson restore names exactly
   ML-09/11/12/13/14; porting them would add ~14 owner-unreviewed questions, new
   objectives, and change the ratified 17-misconception taxonomy. Queued for a
   follow-up owner-reviewed port. The converter header carries the same notice.
2. **Scenario expected answers no longer ship with the page** (finding 7). The
   converter now excludes `scenario.expectedAnswer` from `lesson-pages.json` and
   emits `apps/web/public/pl-400/scenario/<slug>.json`, fetched only after the
   learner commits. Known residual: the scenario section text (including the
   expected answer, prefixed "Expected answer:") remains in
   `lesson-sections.json`, which client bundles must carry because it is the
   rubric verbatim-evidence corpus (agent-less `score_rubric` runs in the
   browser). The commit gate is a pedagogical device; the corpus is a deliberate
   trade-off, documented here.
3. **`lesson-index.json`** (finding 8) is the only lesson artifact client
   bundles may import (routing/scoping/hub-card data, no teaching prose);
   `lesson-pages.json` is server-component-only.
